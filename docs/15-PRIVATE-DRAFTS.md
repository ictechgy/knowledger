# 내 비공개 초안과 편집 재개

저장하거나 [가져온 Markdown](14-MARKDOWN-IMPORT.md)을 새로고침·재로그인 후에도 다시 연다.
화면의 **내 비공개 초안**에는 현재 사용자의 제목·작성일·생성 출처와 초안 수만 표시한다.
다른 사용자의 초안은 목록·개수·상세 조회에서 제외된다.

## 사용 흐름

1. 비공개 초안을 저장한다. 저장 후 **내 비공개 초안** 목록이 갱신된다.
2. 새로고침하거나 다시 로그인한 뒤 목록에서 제목을 선택한다.
3. 저장된 원문을 그대로 공유 검토하거나 본문·제목을 수정한다.
4. **수정 내용을 새 초안으로 저장**을 누른다. 원본 초안은 보존되고 수정본이 별도 항목으로 추가된다.
5. 공유 미리보기에서 본문·수신 조직을 확인한 뒤 게시한다. 합의 승인·채택은 이후 별도 단계다.

저장한 초안을 수정할 때는 문서 ID·context·scope·usage scope·의존성과 공유 parent를 유지한다.
다른 범위의 문서가 필요하면 **새 지식 문서 작성**으로 시작한다. 저장 후 바뀐 내용이 없으면
저장 버튼을 비활성화하며, 내용을 바꾸면 기존 미리보기를 지우고 다시 저장하도록 한다.
계정을 바꾸거나 작성창을 닫으면 이전 목록·원문을 지운다. 늦게 도착한 이전 요청 결과는 표시하지 않는다.

초안은 현재 로컬 저장소에 보존된다. 조직별 외부 vault나 OS 관리자로부터의 강제 격리는
별도 운영 구성이다. 데이터 보존·복원은 [런타임 백업 가이드](16-RUNTIME-BACKUP.md)를 참조한다.

## HTTP 계약

경로는 `/v1/workspaces/{workspace.id}`(예제: `demo`)이며 모든 경로에서 기존 세션·actor 인가를 수행한다.
OIDC 모드는 요청 전후에 현재 계정 권한도 확인한다.

| 경로 | 동작 |
| --- | --- |
| `GET /drafts?limit=20&cursor=<draft_id>` | 본인의 요약 목록·total·next_cursor. limit은 1–50 |
| `GET /drafts/{draft_id}` | 본인의 저장 revision과 private 가져오기/편집 출처 조회 |
| `POST /drafts/{draft_id}/edits` | 원본에서 새 비공개 수정본 생성. 동일 출처·CSRF 필요 |

목록은 작성 시각 내림차순, 같은 시각은 draft ID 내림차순으로 정렬한다. `next_cursor`가 null이면
마지막 페이지다. 다른 사용자의 cursor와 알 수 없는 cursor는 같은404로 거부한다.
목록에는 본문·파일명·내부 요청 digest를 넣지 않는다.

수정 요청 필드는 `edit_id`, `title`, `body_markdown`, 선택적 `source_kind`다.
같은 actor·edit_id·원본·입력은 동시 요청이나 재시작 뒤에도 같은 수정본을 반환한다.
같은 edit_id의 내용이나 원본을 바꾸면409다. 다른 사용자나 존재하지 않는 원본은404다.
새 수정본에는 `source_draft_id`를 private 기록으로 남기며 공유 revision에는 넣지 않는다.
가져온 파일의 원본 hash를 수정한 본문의 hash인 것처럼 복사하지 않는다.

저장된 revision은 digest·도메인 계약·author 바인딩을 확인한다. 손상된 자신의 초안을
정상 문서로 반환하지 않고503으로 보류한다. 리스트·조회·수정은 공유 원장 거래를 만들지 않는다.
