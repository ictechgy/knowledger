# 34. 앱 내부 자동 기한 알림

검토 일정의 담당자에게 기한 도래와 기한 초과를 알려준다. 앱이 실행 중일 때 기본60초마다
처리하고, 브라우저가 보이는 동안30초마다 본인의 알림 목록을 갱신한다. 계정 전환·로그아웃·
숨겨진 탭에서는 이전 응답/타이머를 정리한다. 외부 메시지나 운영체제 예약 작업은 만들지 않는다.

이 문서의 기본 worker는 로컬 알림만 만든다. 별도 opt-in 설정으로 이 알림을 개인 DM에
연결하는 [Slack adapter](38-SLACK-NOTIFICATIONS.md)는 독립적인 권한·전송 상태를 사용한다.

## 생성과 중복 제거

- 기한 이상이면 `due`, 기본24시간 이상 지났으면 `overdue` 알림을 만든다.
- 정확한 개정·일정 버전·수신자·단계별 한 번만 생성한다. DB의 복합 UNIQUE와 트랜잭션으로
  여러 worker/재시작/복원 뒤에도 같은 알림을 다시 만들지 않는다.
- 앱을 오랫동안 껐다가 켰으면 현재 단계 하나만 만든다. 이미 초과 상태라면 도래/초과를
  한꺼번에 보내지 않는다. 시계가 뒤로 움직이거나 초과 기준을 늘려도 overdue 뒤 due를 만들지 않는다.
- 기한은 시스템 UTC 시계 기준이다. 알림은 해당 시점의 운영 기록이며 지식 사용 허가가 아니다.
  올바른 시계 설정이 필요하고, 실시간 전달이나 알림 지연 SLA를 보장하지 않는다.

기한/담당자 변경과 검토 완료는 기존 규칙대로 일정 버전을 올린다. 현재 버전·기한·담당자와
맞지 않는 이전 알림은 목록·읽지 않은 수에서 즉시 제외한다. 반복 검토의 새 주기는 새 버전으로
알림을 받는다. 기록은 삭제하지 않아 snapshot에 남지만 현재 알림 API로 과거 이력을 제공하지 않는다.

알림은 `review_reminders` 테이블에 보관하며 댓글 이벤트, 사람의 결정 또는 공유 원장 거래를
만들지 않는다. 문서 본문·댓글 원문도 알림 테이블에 저장하지 않는다. 수신자의 공개 개정 제목은
목록을 읽을 때 검증된 원장에서 확인한다. 기존 [private DB 백업/복원](16-RUNTIME-BACKUP.md)에 포함된다.

## 인가와 실행 경계

worker는 원장 refresh 뒤 serving 상태와 현재 로컬 persona/membership을 확인한다. 제거된
수신자는 건너뛰고, serving freeze·원장 조회 실패·무결성 오류에서는 알림 생성을 중단한다.
후보 생성은 로컬 저장만 하며 외부 계정/메시지 호출을 하지 않는다. 실제 표시·읽음 처리는
기존 세션/현재 OIDC 인가를 다시 확인하므로 회수된 로그인 권한으로 알림을 읽을 수 없다.

한 tick은 기본50개 후보를 순차 검사한다. keyset 위치를 이어가므로 접근 불가 수신자 때문에
뒤의 후보가 계속 막히지 않는다. 끝에 도달하면 처음부터 다시 검사해 새 후보도 처리한다.
페이지 크기, 앱 가동 상태와 다른 후보 수에 따라 알림 지연이 달라진다. 업무별 알림은 독립적으로
커밋되며 한 배치 전체가 원자적이라는 뜻은 아니다.

refresh에 기본10초 마감을 두고 종료/마감 뒤 늦게 돌아온 조회가 알림을 쓰지 못하게 한다.
앱 종료는 타이머와 진행 중 알림 작업을 중단한 뒤 DB를 닫는다. 오류 원문 대신 안전한
`REMINDER_UNAVAILABLE`을 기록하고 이후 tick에서 재시도한다. 알림은 실패 중 지식의
승인·활성·철회·사용 판정을 바꾸지 않는다.

## 설정

`createApp`/`createConfiguredApp`의 런타임 `reviewReminders` 옵션이다. 미지정 시 활성화하고,
`false`면 생성을 끈다. 이전에 만든 현재 일정의 알림은 비활성화해도 본인이 읽을 수 있다.
설정 JSON schema나 genesis 권한 버전을 변경하지 않는다.

```ts
const app = await createConfiguredApp(configuration, {
  dataDir, port: 4317,
  reviewReminders: {
    pollMs: 60000, timeoutMs: 10000,
    overdueAfterMs: 24 * 60 * 60 * 1000, batchSize: 50,
  },
});
await app.listen(4317);
```

| 옵션 | 범위 |
| --- | --- |
| `pollMs` | 0~3,600,000ms; 0은 자동 생성만 중지 |
| `timeoutMs` | 10~30,000ms |
| `overdueAfterMs` | 1ms~365일 |
| `batchSize` | 1~100 |

가상 시각/명시 실행은 `app.service.reviewReminders.runOnce(nowMilliseconds)`를 사용한다.
HTTP 사용자가 실행 시각을 조작하는 API는 없다. 이 내부 메서드는 테스트/배포 코드용이다.
생성 빈도나 초과 기준을 변경해도 이미 읽은 알림을 새 알림으로 되돌리지 않는다.

## API와 화면

접두사 `/v1/workspaces/:id`, 기존 세션·현재 인가를 요구한다.

| 경로 | 동작 |
| --- | --- |
| `GET /review-reminders?limit=20&cursor=...` | 현재 일정의 본인 알림·읽지 않은 수·자동화 상태 |
| `POST /review-reminders/:id/read` | 빈 객체와 CSRF로 본인 알림 읽음 처리 |

최신순 keyset 목록이며 limit은1~50이다. 각 항목은 reminder ID, 정확한 개정 digest/전체
slot/제목, 일정 버전, 단계, 기한과 생성/읽음 시각을 반환한다. `automation`의 enabled,
poll/overdue 기준, last_error는 안전한 운영 상태다. 본인 것이 아니거나 이미 바뀐 일정의
알림 ID는 읽음 처리할 수 없다.

화면의 **기한 알림**에서 정확한 개정을 연다. 읽음 처리는 검토 완료가 아니고, 완료 버튼도
합의 승인이 아니다. [댓글 전달](33-REVIEW-DELIVERY.md)의 outbox와 연결하지 않으며,
메일·Slack·Teams 알림은 대상 제품과 별도 공개/인가 계약이 정해진 후 추가한다.
