# Claude와 웹 디자인 논의

사용자가 남은 코드 작업을 먼저 진행하면서 웹 디자인은 Claude와 상의하도록 요청했다.
`d9bd6eb`의 화면 파일3개(`index.html`, `style.css`, `app.js`)와 제품 흐름을 전달했고,
Claude Sonnet5의 실제 응답을 받은 뒤 소스와 대조했다. 렌더링된 스크린샷을 검토한 것은 아니다.

## 전달 범위와 실행

`packet-ask`로 선택한 파일을 검사·정리한 패킷은90,917 bytes였다. 패킷 hash는
`39a5d4d123caa175b043ceb349f0652a5696a26176b3a0998f3f22a8f587053d`다.
비공개 초안·DB·인증서·키는 전달 대상에 포함하지 않았다.

packet-ask 전용 Claude 인증은 없었으므로, 정리된 paste 패킷을 기존 Claude 구독 CLI에 stdin으로 전달했다.
작업 디렉터리는 별도 임시 폴더였고 safe/restricted mode, 도구 없음, MCP 없음, 별도 세션 저장 없음으로
검토만 요청했다. 부모 셸이나 전역 모델 설정은 변경하지 않았다.
원본 응답과 실행 metadata는 Git 제외 `.artifacts/design/`에 보관한다. 외부 출력은 구현 권한이나 검증 증거를 대신하지 않는다.

## 주요 제안과 판단

| Claude 제안 | 소스 대조와 반영 방향 |
| --- | --- |
| 한 컬럼에 모든 작업이 쌓여 있어 주 행동이 불명확 | 확인했다. 검토함 / 문서·초안 / 실행 컨텍스트로 나누는 방향을 채택하되 코드 작업 뒤 단계적으로 적용 |
| 게시만 된 문서와 검토 중인 문서의 배지가 같음 | 확인했다. 상태 어휘를 세분화하고 게시와 합의를 분리 |
| pending 안내가6.5초 후 사라짐 | `showStatus()`에서 확인했다. 시간만으로 미확정 안내를 숨기지 않도록 우선 보완 |
| raw ID·digest·manifest가 기본 화면에 많음 | 제목·상태·업무 범위를 먼저 보이고 증거는 접기/펼치기로 제공 |
| 비공개 초안과 공개 검토의 시각적 차이가 약함 | 단계 이름과 원문/수신 조직 확인을 유지하고 후속 layout에서 경계를 강화 |
| 작은 faint 텍스트의 대비가 낮음 | 토큰 계산상 surface 대비3.60:1. 필수 작은 텍스트에는 muted 이상의 대비 사용 |
| 모바일 문서 목록을 세로로 정리 | 현재460px 이하는 이미1열이다. 실제3열이 남는461–760px 구간을 후속 대상으로 한정 |

“로그인 후 항상 내 검토함”은 모든 역할에 그대로 적용하지 않는다. 처리할 검토가 없는 작성자와 조회 사용자에게는
문서·초안 진입이 필요하다. 또한 응답 수가 찼다는 표시나 버튼 노출이 서버의 승인·활성화 검증을 대체할 수 없다.

## 순서

1. 조직별 실행·인가·서명·복구 코드를 완성하고 실제 Fabric에서 검증한다.
2. 미확정 안내와 상태 이름처럼 오해를 만드는 작은 동작부터 보완한다.
3. 검토함, 기술 증거 접기, 작업 공간 분리, 타이포/밀도 조정 순으로 구현한다.

이번 코드 작업에서는2번의 작은 동작을 반영했다. pending의6.5초 자동 숨김을 제거했고,
목록/상세에서 공유 게시·검토 중·합의 활성·현재 사용 보류·대체를 구별한다.
브라우저에서 타이머 전후와 새 게시본의 합의 전 표시를 확인했다. 거래별 지속 추적 목록이나
전체 작업 공간 재배치는 아직 구현하지 않았다.

채택한 원칙과 아직 구현하지 않은 배치를 [DESIGN.md](../DESIGN.md)에 구분해 기록했다.

## 후속 구현 — 2026-09-16

범용 설정 구현과 함께 검토함, 세 영역 내비게이션, 정확한 개정 선택, 기술 증거 접기,
정책에서 자동 설정하는 문서 범위, 작은 작업 제목과 760px 이하 세로 목록을 반영했다.
설정의 workspace·조직·맥락·역할 라벨을 사용하며, 로컬 계정은 조직과 actor를 함께 선택한다.

격리된 agent-browser에서 초안→미리보기→게시→두 조직 승인→활성→컨텍스트 제공과
계정 전환 시 비공개 초안 제거를 확인했다. 같은 문서의 새 게시본이 있어도 검토함은
해당 제안의 과거 개정 원문을 정확히 연다. 390/600/1440px에서 DOM의 가로 넘침이 없고,
600px 문서 목록은 한 열이다. native click이 반영되지 않는 CLI 제약 때문에 일부 행동은
같은 브라우저의 DOM 이벤트로 검증했다. screenshot 명령은 응답하지 않아 종료했으며,
스크린샷 비교나 전체 접근성 인증을 완료했다고 주장하지 않는다.
